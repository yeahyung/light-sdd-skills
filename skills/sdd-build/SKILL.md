# SDD Build

원문·명세·데이터·코드·실제 답변을 확인한다. 한국어 문어체로 작성하고 확정·위임·미정을 구분하며, 실행한 검증만 통과로 표시한다.

## 구현 전·도중의 판단

- 원문·확정 답변의 요구사항만 구현한다. 누락·충돌·코드 차이를 확인하고, 명세가 없으면 완료 조건을 정리한다.
- 기존 변경을 보존하고 구현 순서를 알린다. 결과에 영향 없는 기술 선택은 자율 판단하고 선택·이유·영향을 기록한다.
- 구현 전·도중에 자료로 확인되지 않은 결과·범위·통과 조건의 모호함을 발견하면 반드시 사용자에게 질문한다. Q번호·구현 차이·선택지·추천 이유를 기록한다.
- 답변 또는 해당 결정의 명시적 위임 전까지 의존 Feature는 보류하고 독립 작업만 계속한다. 무응답은 미정으로 유지한다. 실제 답변을 명세에 반영하고 영향받은 코드를 수정·재검증한다.

## 구현과 검증

- 입력 → 검증 → 처리 → 저장 → 출력의 필요한 흐름부터 연결하고 규모에 맞게 책임을 나눈다.
- 알고리즘·핵심 선택 로직은 입력 → 규칙 → 출력으로 설명하고 선택 이유·한계·근거 파일·함수를 적는다. 우선순위·동률·예외 처리·휴리스틱의 보장 범위도 해당하면 설명한다. 1~3줄로 시작하되 이해에 필요한 예시는 보충한다.
- 실제 입력과 기대 결과로 통과 조건을 확인한다. 계산은 독립 검산하고 사용자 흐름·오류·경계값을 검증한다. 기대값은 합의된 규칙·원본 입력에서 도출한다.
- 수정·검증 기준 변경 후 원래 사례와 영향받는 기능을 재검증한다. 기준 변경 근거를 기록한다. Docker·영속성이 요구되면 빌드·기동·재시작 후 데이터를 확인한다.
- 사용자가 병렬 작업을 명시적으로 요청한 경우에만 서브에이전트를 사용한다. UI만 요청하면 UI 담당만, 테스트만 요청하면 테스트 담당만 사용하며, 명시적으로 요청하지 않은 작업에는 서브에이전트를 사용하지 않는다. 병렬화 대상은 화면 렌더링(UI)과 테스트 작업으로 한정하며, 핵심 도메인 로직·저장소·라우팅 통합은 주 담당이 순차적으로 처리한다.
- 병렬 작업을 시작하기 전에 주 담당은 화면에 전달할 데이터·상태 이름·URL 등 필요한 계약과 각 담당자의 수정 가능 파일 범위를 정한다. UI 담당은 템플릿·정적 파일과 표시 로직만, 테스트 담당은 검증 스크립트·테스트 fixture·검증 문서만 수정한다. 다른 담당자의 파일이나 계약을 임의로 바꾸지 않는다.
- UI·테스트 담당의 결과는 주 담당이 통합한다. 통합 뒤 실제 전체 검증을 다시 실행하며, 서브에이전트의 완료 보고나 테스트 초안만으로 통과를 표시하지 않는다. 요청한 병렬 범위를 벗어난 구현은 주 담당이 순차 처리하고, 범위 확대가 필요하면 사용자에게 확인한다.

## 시간과 결과 관리

- 확정 범위의 구현·검증을 우선한다. 판단·오류·수정·재검증은 기존 기록에 남기고 민감값은 가린다.
- 결과표에는 원문 필수 항목과 Feature의 연결을 확인한다. 보고용 반복 검증은 줄이고 수정·실패·관련 변경에는 재검증한다. 정밀 교차 점검은 사용자 요청 시 sdd-verify에서 수행한다.
- 검증 결과는 `통과·실패·미검증·사람 확인 대기`다. 실패가 우선이며, 미구현·핵심 동작 미실행·필수 검사 누락은 미검증이다. 수행 가능한 필수 검증을 실제 통과하고 사람의 UI 확인만 남으면 사람 확인 대기로 기록한다. 검사 0개는 통과 근거가 아니다.
- Feature 상태는 `미착수·완료·보류`다. 완료는 구현 완료이며 근거를 연결한다. 사람 확인 대기만 남으면 “구현 완료, 사용자 확인 N건 대기”로 보고하고 확인 절차·기대 결과를 남긴다.
- [result.template.md](result.template.md)를 채워 `spec.md` 끝의 `## 구현 결과`를 추가·갱신한다. 명세가 없으면 `result.md`에 저장한다. 미해당 항목은 없음으로 적는다. 자율 판단·명시적 위임·사용자 확정은 구분하고 선택·이유·영향을 설명한다.
- 채팅은 작업·검증·사용자 확인·연결되지 않은 원문 항목·주요 판단을 짧게 요약하고 상세 파일을 연결한다. 알고리즘·로직은 해당할 때 설명한다.

## 필수 기준

- 원문 필수 요구사항을 빼지 않는다.
- 없는 데이터·담당자 답변을 만들지 않는다.
- 미구현이나 필수 검증의 실패·미검증을 완료로 표시하지 않는다.
- 원문·확정 답변에 없는 기능과 업무 규칙을 추가하지 않는다.
