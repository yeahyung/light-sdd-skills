# SDD Verify

기능이 있다는 설명과 실제 완료 증거를 구분한다. 지정된 원문·명세·확정 답변·코드·데이터·실행 결과만 사용한다.

한국어 문어체로 작성하고 확정·위임·미정을 구분하며, 실행한 검증만 통과로 표시한다.

## 점검 범위

- 기존 검증 결과와 이후 관련 코드·입력 데이터·설정의 변경 및 병렬 작업의 통합 여부를 확인한다. 영향받는 항목은 재검증하고, 변경의 영향을 받지 않은 증거는 재사용한다. 현재 상태와 연결되지 않는 과거 통과 기록은 현재 기능의 성공 근거로 삼지 않는다.
- 원문·확정 답변의 요구사항 → 명세의 Feature·공통 완료 조건 → 구현 위치 → 검증 방법·실제 결과를 연결한다. 명세에서 누락된 원문 항목·불일치·요구 밖 추가도 확인한다. 결과는 통과·실패·미검증·사람 확인 대기로 구분하고 미확인 사항과 적용 제외 이유를 남긴다.
- 다음 중 원문·확정 답변에 해당하는 것만 확인한다.
  - 명시된 실행 명령과 배포·전달 형식. 컨테이너가 요구되면 최종 코드의 빌드·기동.
  - 각 사용자 역할의 핵심 흐름, 화면 결과와 저장·조회 값의 일치.
  - 업로드·수정·재계산·재조회. 잘못된 입력이 기존 정상 데이터를 훼손하는지 여부.
  - 주요 제약·단위·시간 기준·경계값·처리 불가능한 상황.
  - 저장 지속성이 요구되면 지정된 재기동 절차 뒤의 결과.
  - README·구현 결과의 실행 방법·기능·알고리즘·선택 규칙·한계 설명과 실제 코드의 일치. 선택 이유는 작업 기록에 근거하고 확인되지 않은 이유는 미확인으로 남긴다.

## 실행과 수정

- 기대값의 근거가 합의된 요구사항·원본 입력·독립적인 계산인지 확인한다. 실제 출력과 다르다는 이유만으로 기대값을 바꾸지 않는다. 기준의 오류를 고칠 때는 변경 이유와 근거를 남긴다.
- 자동 검사의 종료코드와 함께 실제로 실행된 항목·실패·건너뜀을 읽는다. 검사가 발견되지 않았거나 핵심 항목을 건너뛴 실행을 해당 기능의 통과로 표시하지 않는다.
- 단위 검사, 외부 의존성을 대신한 대역 검사, 실제 연동, 사용자 흐름 검증의 범위를 구분한다. 일부 단계의 통과를 전체 흐름이나 실제 외부 연동의 성공으로 확대하지 않는다.
- 테스트 데이터나 분리된 복사본으로 점검하고 원본 입력을 보존한다. 실제 외부 시스템의 변경을 로컬 검증과 혼동하지 않는다.
- “검토만”이면 결함과 재현 증거만 보고한다. 수정 요청 또는 기존 구현 작업의 수정 권한이 있으면 합의된 범위에서 작은 수정을 적용하고 같은 검증을 다시 수행한다.
- 새로운 업무 결정이나 큰 범위 변경이 필요하면 그 결정만 확인한다. 이미 허용된 작은 수정에는 반복 승인을 요구하지 않는다.
- 최종 점검 중 새 선택 기능이나 대규모 리팩터링을 시작하지 않는다. 남은 시간이 없거나 실행 환경이 막히면 미검증을 명시한다.

## 항목별 설명

각 Feature와 공통 완료·제출 조건을 다음 순서로 설명한다. 항목마다 1~2문장으로 시작하고, 도메인 지식 없이 이해할 수 있는 말과 필요한 예시를 사용한다.

- 요구와 구현: 명세의 기대 결과와 실제 동작의 일치·누락·차이.
- 알고리즘·로직: 실제 입력 → 검증·계산·선택 규칙 → 저장·출력과 근거 파일·함수. 우선순위·동률·예외 처리는 해당할 때 설명한다. 별도 알고리즘이 없는 항목도 실제 처리 순서를 적는다.
- 검증: 실행한 방법·확인 범위·결과와 남은 사용자 확인 절차. 코드 읽기로 확인한 내용과 실행 증거를 구분한다.
- 주요 판단·한계: 자율 판단·위임·확정의 구분과 선택 이유·영향. 이유의 근거가 없으면 미확인으로 남긴다.

## 결과

교차 점검의 충족·누락·불일치·요구 밖 추가와 실패·미검증 항목을 근거와 함께 알린다. 구현 결과가 있으면 기존 검증 표·연결되지 않은 원문 항목·수동 확인 항목을 갱신한다. 필수 요구의 실패·미검증이 남으면 미완료로 보고한다. 수행 가능한 필수 검증을 실제 통과하고 사람의 UI 확인만 남으면 사람 확인 대기로 분리하여 “구현 완료, 사용자 확인 N건 대기”로 보고한다. 핵심 동작 미실행·검사 누락·실패를 사람 확인 대기로 대체하지 않는다. 실제 확인 결과를 받으면 검증 상태와 체크리스트를 갱신한다. 별도의 장문 보고서는 요청됐거나 인수인계에 필요한 경우에만 만든다.
